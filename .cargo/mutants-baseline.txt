# One line per survivor: the mutant's name as cargo-mutants prints it, with the line and column
# removed (`src/x.rs:12:5: replace ...` becomes `src/x.rs: replace ...`). Positions move with every
# edit above them; the file, the mutation and the function it is in do not. A mutation that survives
# in two places in one function appears twice, and is compared as a count.
#
# Taken from the first full sweep, 2026-10-05 at 260f4d8, minus the Windows-only modules that
# `mutants.toml` now excludes. That sweep did not finish: shard 25 uploaded nothing and four
# shards ran out of time, so about 130 mutants were never tested. The run of 2026-10-22 at
# 555286a tested them; shard 15 lost its runner after 59 of its 71, and the other 12 were run
# locally the same day. Its 40 survivors in `#[cfg(windows)]` functions were added here; its 8 in
# code the Linux tests run were killed instead, and one that hung the suite is now bounded.
# The run of 2026-10-22 at ce4a51f, the first to pass in full, was then counted across all its
# shards: two survivors this list was short of were added (a shard sees only its own, so a name
# surviving once in each of five shards had passed against four lines), and two lines nothing
# survived were deleted. A third deletion was wrong: a rerun of the same source on 2026-10-23
# showed that mutant had been "caught" by a flaky test, as were four others, and it is back. Both
# flaky tests are fixed. That made it each name's highest count across those two runs, 397, which
# the next full run (2026-10-23, da665c1) matched line for line. 15 of the 17 lines in `auth.rs`
# were killed on 2026-10-24, leaving 382. Adding a line is a decision, not a formality.
#
# Every line is debt, not an exemption: a test gap, a `#[cfg(windows)]` function inside a shared
