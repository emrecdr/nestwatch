What it does

Everything below is in the dashboard. The two controls that actually hold are the daily budget and the curfew — the rest shapes habits.

Daily budget

Time, counted honestly

A minutes-per-day limit, optionally different for each weekday. Counts only active use — not idle, locked or logged-out time — survives reboots, and resets at midnight. When it's spent: lock, shut down, or just warn.

Curfew

Bedtime that arrives quietly

One or more time windows per weekday. The child sees a countdown at 15, 5 and 1 minutes, then the machine shuts down — and re-issues if the shutdown is cancelled.

Warnings

The limit is never a surprise

Countdowns at 15, 5 and 1 minutes for both the budget and bedtime. A budget shorter than a threshold never announces it, a mid-day restart doesn't replay warnings, and granting extra time re-arms them.

Screen-time report

The week, not just today

Thirty days as a chart, with per-app minutes and a comparison against the period before. Days the service wasn't running show as not measured rather than zero, so a stopped enforcer can't be mistaken for a quiet week.

Asking for more

A way to say yes

The child's own page shows how much time is left and can request more; the parent approves or denies. Single-use offline codes cover the times you're away or the network is down.

Remote control

See and act

Screenshot the desktop with an optional live refresh, list running apps and close one, lock the screen, or power the machine off with a warned countdown.

App rules

Blocklists and pools

Named apps closed on sight, per-app daily limits, and groups that share one pool — all the games together get ninety minutes between them. Habit-shaping, not a wall (see below).

Modes

One toggle for a free evening

Pause the whole rules enforcer with a switch — curfew still applies. Save the current setup as a named routine and reapply it with a click.

Trust the setup

A doctor that answers

One command reports whether the service is up, the port is listening, the firewall rule is right, the network is private, how long the certificate has left, and whether anything is actually being enforced. Every problem prints its fix.

How it works

One binary. On Windows it installs as a background service that serves the dashboard over HTTPS and runs two independent enforcers. Because that service has no desktop of its own, anything needing the screen is delegated to a short-lived helper.

How it's kept closed

The thing being protected is a session that can watch a screen and power off a machine. It sits behind several independent layers, so one failing doesn't open the door.

Reach

Two separate network gates

A firewall rule scoped to the local subnet, and an application-level check that refuses anything off-LAN. Either alone would do; both have to fail together.

Transport

HTTPS you can verify

A self-signed certificate whose SHA-256 fingerprint is printed at install and reprintable on demand, so you can confirm you're talking to the right machine rather than something else on the network.

Login

One password, slow to guess

Argon2id hashing, per-IP throttling that a stranger can't use to lock the parent out, and sessions that survive a reboot so you're not retyping a passphrase on a phone.

Cross-origin

Requests checked for origin

A login cookie alone can't tell this dashboard apart from a page served on a different port of the same PC. Every request is checked against the browser's own report of where it came from — while links, bookmarks and the pairing QR keep working.

On disk

Out of the child's reach

The password hash, the TLS key and every log live in a directory restricted to the system and administrators. A standard user can't read them, alter them or delete them.

Record

Actions are logged

Logins with their source address, and every sensitive action, in append-only logs the dashboard can show you. Daily screen-time totals are kept in a separate file so ordinary event volume can't push the history out.

The whole model rests on one assumption: the child's Windows account is a standard user, not an administrator. An administrator can undo any of this. It's the first thing to check, and it's worth more than every other measure combined.

What it deliberately doesn't do

A tool like this is worth less if it overstates itself. These are real limits, not oversights.

  • App rules are speed bumps, not walls. Apps are matched by filename, so a child who copies an executable under another name in a folder they can write to is no longer blocked. Nothing short of kernel-level enforcement closes that. Use app rules to steer everyday habits and rely on the budget and curfew — which aren't name-based — for limits that have to hold.
  • Time is counted while an app runs, not while it's watched. Something left open in the background still consumes its limit. That makes per-app limits impractical for anything that starts itself, and it means the figures aren't comparable to the numbers a phone reports.
  • Totals are per-machine, not per-account. Whoever is signed in at the keyboard adds to the same total — including you.
  • No keylogging, no browsing history, no microphone, no location. Not oversights: the point is a time limit a household can agree on, not surveillance.
  • An administrator on the PC can defeat all of it. Out of scope by design.
  • It watches its own pulse, but doesn't yet repair itself. If an enforcer stops, the dashboard says so rather than quietly reporting a quiet day — but restarting it is still a person's job.

Install & verify

Written to be followed on your phone while you stand at the PC.

  1. Get the build

    Download nestwatch.exe and nestwatch.exe.sha256 — you need both.

    Latest release

  2. Verify it before you run it

    In PowerShell, in the folder you downloaded to:

    Get-FileHash nestwatch.exe -Algorithm SHA256 | Format-List

    Open the .sha256 file and check it matches, character for character. If it doesn't, delete the download and fetch it again. This binary will run with administrator rights on your child's machine — it's worth thirty seconds.

    Stronger, if you have the GitHub CLI: the hash only proves the download didn't corrupt — it ships from the same place as the file. This instead checks a signature proving the binary was built by this repository's release workflow:

    gh attestation verify nestwatch.exe --repo emrecdr/nestwatch

  3. Unblock and install

    Right-click the file → Properties → tick Unblock. Then, from an elevated PowerShell:

    .\nestwatch.exe install

    Write down the certificate fingerprint it prints. You need it once per device you pair.

  4. Pair a device

    Scan the QR code it shows. It opens the dashboard already signed in, and the link works exactly once.

  5. Confirm it actually works

    Installing cleanly isn't the same as working:

    • The dashboard loads from your phone, and the certificate warning shows the fingerprint you wrote down.
    • A screenshot returns the live desktop rather than a black image.
    • The managed account is a standard user, not an administrator.
The full step-by-step list — what each check proves, and what to do when one fails — lives in the on-device checklist. Work through it once on the real machine; several things can only be verified there.
